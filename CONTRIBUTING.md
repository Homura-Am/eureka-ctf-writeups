# Adding a write-up

1. Create one Markdown file at `<year>/<event>/<challenge>.md` using lowercase names and hyphens.
2. Explain the challenge, the vulnerability or key insight, the solving steps, and the result. Include exact commands and code where they help someone reproduce the solution.
3. Include relevant solution code directly in fenced code blocks in the Markdown file. Record dependencies and any required setup. Screenshots are optional.
4. Add the challenge link to the root README, then update the event list and write-up count.
5. Open a pull request with a short description of the challenge and what you checked.

Use verified facts and captured output. Label assumptions and unconfirmed details clearly; distinguish a reconstructed script from the original working solution. Credit the people and references involved, including tools or AI assistance where required by the event's submission rules.

Before submitting, check that links work and commands match the included code. Keep credentials, API tokens, private conversation links, and unrelated personal files out of commits. Follow the event's write-up release timing.

The repository owner can invite teammates through GitHub's repository access settings. Teammates can then contribute through branches and pull requests.
